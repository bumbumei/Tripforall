## Slide 3 · 문제 정의

### 한국 관광은 새로운 트렌드(D.U.A.L.I.S.M.)에 진입했지만, 도구는 따라가지 못합니다

| 현실 | 기존 서비스 한계 |
|---|---|
| 고령화·돌봄 가족 증가 → 휠체어·임산부 동반 비중 급증 | 무장애 정보 흩어짐, "동행자 전원에게 맞는" 추천 부재 |
| 3세대 동반 여행 증가 (조부모-부모-자녀) | 가장 느린 사람 기준 페이스·세대별 관심사 충돌 미해결 |
| 현지인·웰니스·반려동물 등 다양한 테마 수요 | 테마별 큐레이션 없음 — "관광지 리스트" 나열 |
| 운영시간·휴무·날씨 따른 동선 변경 필요 | 클릭 후에야 "오늘 휴무"를 알게 됨 |

**👉 이동약자 본인이 아니라 동행 가족이 여정을 짜야 하는 경우, 무장애 + 동선 + 휴무 + 세대 분기를 한 번에 챙기는 도구가 없습니다.**

## Slide 4 · 솔루션 한 장

### "동행자 전원이 함께 걸을 수 있는 코스"를 한 번에 생성

```
[사용자 입력]
시·도·시군구 / 동행자(이동수단·체력·연령) / 테마 / 식사 / 날짜·시간
        │
        ▼
[14종 외부 데이터 수집] (백엔드 병렬 호출, 5초 timeout 적용)
KTO 5종 · 행안부 식당/화장실 · KCISA · Open-Meteo
국립의료원 응급실 · 지하철 엘리베이터
        │
        ▼
[Ennoia 에이전트 3종 병렬 추론] (gpt-4o-mini, ~4초)
pace 시뮬 / wellness 점수 / multiGen narrative+분기
        │
        ▼
[결과] 안전 동선 + 무장애 표기 + 휴무·날씨 회피 + 응급실·화장실 매핑
       (총 응답 시간 ~15초)
```

**핵심 차별점**
- ✅ **가장 느린 동행자** 기준 코스 (체력 30% 미만 → 자동 휴식)
- ✅ **세대 분기** + 재합류 + bonding 미션
- ✅ **휴무/날씨 자동 회피** → 변경 안내
- ✅ **"다른 조합 보기"** — 같은 입력으로 즉시 재생성

## Slide 5 · 주요 기능 (1/2)

### ① 무장애 매칭
- KTO **무장애 여행 정보 서비스** (KorWithService2) 우선 호출
- 휠체어·엘리베이터·화장실·경사로·인력 안내 **25항목** 검증
- 휠체어(수·전), 유아차, 보행보조기, 저체력, 임산부, 아동, 일반 — **8종 이동수단** 지원

### ② 테마 큐레이션 (10종)
역사·자연·음식·예술·가족·축제·**현지인처럼**·**실내**·**웰니스**·**반려동물**
- 테마별 score 함수 + 날씨 modifier(비 → 실내 가산점)
- 웰니스/반려동물은 **전용 KTO API** 직접 호출

### ③ 동선 최적화
- 4개 시·도(서울 25 / 부산 16 / 제주 2 / 경기 31) — **74개 구·시·군**
- 시·군·구 반경(5~18km) 내 후보 → 시작점 기반 인접거리 정렬
- 평균 4~6 stop · 인접 leg 거리 km 표시

## Slide 6 · 주요 기능 (2/2)

### ④ 동행자 체력 시뮬 (pace 에이전트)
- 각 segment별 staminaCost(−소비/+회복) 계산
- 동행자별 잔여 체력 추적, 30% 미만 → 자동 휴식 segment 삽입
- 안전 여부(`safe`) + 최저 체력 요약

### ⑤ 세대 연결 동선 (multiGen 에이전트)
- segment 타입: `common` / `split` / `rejoin` / `meal`
- 활동적인 가족 짧게 분기 → 다시 합류 (예: 할머니 그늘 벤치, 어머니·손주 경회루 산책)
- **bonding 미션** 1~2회 (예: "근정전에서 할머니께 학창시절 이야기 듣기")
- 1인칭 **narrative** 6~10단락 (사용자가 "미리 다녀온 일기"처럼 읽음)

### ⑥ 운영시간·휴무·날씨 회피
- TourAPI `restdate`(요일 휴무) + `usetime`(영업시간) 파싱
- 사용자 시작 시간 기준 못 들어가면 **휴무 사유 + 시간 변경 안내**
- Open-Meteo 현재 날씨(WMO code) → 비/눈 시 실내 테마 가산점

### ⑦ "다른 조합 보기" + 코스 재구성
- shuffleSeed 변경 → 같은 입력으로 anchor 변경
- 추천 풀에서 spot 선택 → forceSpotIds로 그 장소 중심 재계산

## Slide 9 · 시행착오 및 개선시도

### ① Ennoia 인증 user_id 문제 ⚠ → ✅
- **문제**: API 호출 시 `MCP_CONNECTION_REQUIRED` 에러 반복
- **삽질**: `X-ENNOIA-USER-ID`에 이메일(`bumbumei@gmail.com`) 시도, user ID 후보 6종(`admin`, project ID 등) 모두 실패
- **발견**: Studio deploy log JSON의 `user_id` 필드가 **32자 hex UUID** (이메일 아님)
- **해결**: env 변경 → **HTTP 200, KTO MCP 정상 호출 확인** (`kto_barrier_free_locationBasedList2`)

### ② Ennoia 응답 41초 → 4초 ⚡
- **문제**: 첫 preset(KTO MCP 63 도구 + gpt-5)이 모든 호출에 41초
- **분석**: 우리 백엔드가 이미 14종 API로 KTO 데이터 수집 → MCP 중복
- **해결**: **추론전용 preset** 신규 생성 (gpt-4o-mini, MCP 없음)
- **결과**: 단순 JSON 4.2초 / multiGen narrative 14.8초

### ③ 외부 API 70초 → 7.6초 🚀
- **문제**: KCISA 맛집 API가 60초 → 전체 응답 70초
- **해결**: fallback 체인 재정렬 (**TourAPI → 행안부 → KCISA**) + 모든 호출 `AbortController` 5초 timeout
- **결과**: 7.6초 (10배 단축)

### ④ NO_COURSE 버그 (강남구·실내 테마) 🐛 → ✅
- **문제**: 시작 10:00, 강남구·실내 → "코스 생성 불가"
- **원인**: 모든 실내 후보가 11시 개점 → 운영시간 필터에서 전부 탈락
- **해결**: 열린 곳이 0이면 **picked spot 유지 + 휴무 사유와 시간 변경 안내** 함께 표시
- **부수효과**: 사용자가 "왜 이게 안 되는지" 이해할 수 있게 됨

### + 프롬프트 튜닝
- narrative 톤: 형식적 → **"미리 다녀온 사람의 일기"처럼 1인칭**
- bonding 미션: 추상적 → **"손주가 할머니께 학창시절 이야기 듣기"** 같은 구체적 행동
- JSON 모드: OpenRouter는 `extractJson` 함수로 ```json ... ``` 마커 제거 후 파싱

## Slide 10 · 기대 효과 + 차별화

### 기대 효과
| 대상 | 변화 |
|---|---|
| **이동약자** | "어차피 못 가" → "할머니도 같이 갈 수 있어" |

| **여행 기획자** (자녀·요양보호사 등) | 무장애 + 휴무 + 응급실 확인을 한 번에 — **수십 개 탭 → 한 화면** |
| **관광공사·지자체** | 무장애 인증 데이터의 실수요 입증 + 미인증 시설 보강 우선순위 도출 가능 |
