## Q5 시행착오 — 폼 그대로 사용

네, 크게 4가지가 있었습니다.

**① Ennoia 에이전트 호출 인증 문제 해결**
처음 Ennoia API 호출 시 `MCP_CONNECTION_REQUIRED` 에러가 반복됐습니다. `X-ENNOIA-USER-ID` 헤더에 이메일을 넣었지만 인증되지 않았는데, **deploy log JSON의 `user_id` 필드가 32자 hex UUID인 것**을 발견하고 그 값으로 교체해 해결했습니다. Ennoia 내부 user ID 체계(이메일이 아닌 내부 식별자)를 정확히 이해하는 계기가 됐습니다.

**② Ennoia 응답 시간 41초 → 4초 단축**
처음 사용한 preset은 한국관광공사 MCP 63개 도구 + gpt-5라서 모든 호출이 41초 걸렸습니다. 우리 백엔드가 이미 14종 API로 KTO 데이터를 다 수집한다는 점을 활용해 **"추론전용" preset(gpt-4o-mini, MCP 없음)을 별도로 만들고**, 추론 작업과 데이터 수집을 분리했습니다. 단순 JSON 호출은 4.2초, 긴 narrative 생성도 14.8초로 줄였습니다.

**③ 외부 API 응답 지연 70초 → 7.6초**
KCISA 시티투어 맛집 API가 60초 걸려서 전체 여정 생성이 70초까지 늘어났습니다. 식당 정보 fallback 체인을 **TourAPI → 행정안전부 일반음식점 → KCISA** 순으로 재정렬하고 모든 외부 호출에 `AbortController` 5초 타임아웃을 적용해 7.6초로 단축했습니다.

**④ 강남구·실내 테마 NO_COURSE 버그**
사용자 시작 시간 10:00에 강남구·실내 테마를 선택하면 코스가 생성되지 않는 문제가 있었습니다. 원인은 추천된 모든 실내 장소가 11시 개점이라 운영시간 필터에서 전부 탈락한 것이었습니다. **"열린 곳이 하나도 없으면 닫힌 picked spot을 유지하고, 사용자에게 휴무 사유와 시간 변경 안내를 함께 보여주는"** 로직으로 수정했습니다.

이 외에도 narrative가 너무 형식적이어서 **"미리 다녀온 사람의 일기"처럼 1인칭으로** 톤을 변경했고, 세대 연결 bonding 미션이 너무 추상적이지 않게 **"손주가 할머니께 학생 시절 이야기 듣기"** 같은 구체적 행동으로 프롬프트를 여러 차례 수정했습니다.
