## 슬라이드 5 — 서비스 한 줄 요약

(중앙 큰 글씨)

> ### "우리는 **이동약자와 다세대 가족이 함께 갈 수 있는 여행 코스가 없다는 문제**를 **무장애·페이스·세대분기를 통합한 AI 동반자**를 통해 해결합니다."

**핵심 기능 3가지**
1. **무장애 매칭** — 휠체어·엘리베이터·화장실 등 KTO 검증 25항목 + 행안부 화장실 통합
2. **다세대 동선** — 가장 느린 동행자 기준 + 활동적인 가족 분기/재합류 + 세대 연결 bonding 미션
3. **선제적 위험 회피** — 휴무·날씨·체력 30% 미만 시 자동 변경/휴식 + 응급실 매핑

## 슬라이드 11 — 한국관광공사 OpenAPI 활용 경험

### 왼쪽: 서비스 개발에 활용한 한국관광공사 OpenAPI List (5개)

| # | API명 | 상세 설명 |
|---|---|---|
| 1 | **국문 관광정보 서비스** (KorService2) | 관광지·식당 기본 검색 + 상세 (areaBasedList2, detailCommon2, detailIntro2, detailInfo2, detailImage2) |
| 2 | **무장애 여행 정보 서비스** (KorWithService2) | 휠체어·엘리베이터·화장실·경사로·인력 등 **25항목** — 본 서비스의 핵심 데이터 |
| 3 | **반려동물 동반여행 서비스** (KorPetTourService2) | 반려동물 테마 전용 추천 풀 |
| 4 | **웰니스 관광정보 서비스** (WellnessTursmService) | 웰니스 테마 전용 풀 (langDivCd=ko) |
| 5 | **관광지 집중률 방문자 추이 예측 정보 서비스** (TatsCnctrRateService) | 혼잡도 🟢🟡🔴 표시 (areaCd + signguCd 법정동 5자리) |

> 양식 제공 박스는 4개지만 우리는 5개 사용 — 박스 1개 추가하거나 5번을 List 1·2 박스에 추가 표기 가능.

### 오른쪽: 한국관광공사 OpenAPI 외 활용 자료

- **행정안전부 모범음식점 정보 조회 서비스** — `🏅` 인증 배지
- **행정안전부 식품 일반음식점 조회 서비스** — 기본 식당 풀 보강
- **행정안전부 휴게음식점 조회 서비스** — 카페 풀
- **행정안전부 관광식당 조회 서비스** — `🍽` 관광식당 인증
- **행정안전부 공중화장실 표준데이터셋** — 장애인 화장실 반경 500m 매칭 (preloaded 1.7MB)
- **KCISA 시티투어 맛집 API** — 광역 도시 맛집 fallback (5초 timeout)
- **Open-Meteo 기상 API** — 실시간 날씨 (WMO code → preferIndoor 가산점)
- **국립중앙의료원 응급의료기관 API** — 코스 중심 좌표 기준 응급실 2곳 자동 매핑
- **서울 열린데이터광장 지하철 엘리베이터 데이터** — 역 접근성 (preloaded 138KB)

**합계 14종 외부 데이터**

> ⚠️ 구글폼 ⑤ 활용 API 선택 시 **위 5개 KTO API만 체크** — 다른 21종(외국어, 사진, 캠핑, 오디오 등)은 실제 호출하지 않으므로 미선택.

## 슬라이드 12 — 시행착오 & 개선시도

### 왼쪽: 시행착오

- Ennoia 에이전트 호출 시 인증 실패 (`MCP_CONNECTION_REQUIRED` 반복)
- 첫 preset 응답 시간이 41초로 너무 느림 (3 task 병렬 호출 시 사용자 대기 60초+)
- 외부 KCISA API 응답이 60초까지 늘어져 전체 여정 생성 시간이 70초까지 폭증
- 강남구·실내 테마에서 `NO_COURSE` 에러 — 모든 후보가 11시 개점, 사용자 시작 시간 10시 충돌

### 오른쪽: 개선시도 (4건)

| # | 개선시도 | 개선결과 |
|---|---|---|
| **1** | Ennoia deploy log JSON을 분석해 `user_id` 필드가 **32자 hex UUID**(이메일 아님)임을 발견, `X-ENNOIA-USER-ID` 헤더 교체 | HTTP 200 정상, KTO MCP 63개 도구 호출 성공 (`kto_barrier_free_locationBasedList2` 실호출 확인) |
| **2** | **"추론전용" preset 신규 생성** (gpt-4o-mini, MCP 없음). 우리 백엔드가 이미 KTO 데이터 수집한다는 점 활용 — 추론과 데이터 수집 분리 | **41초 → 4.2초** (단순 JSON) / **14.8초** (긴 narrative) — 약 10배 단축 |
| **3** | 식당 fallback 체인 재정렬 (**TourAPI → 행안부 → KCISA**) + 모든 외부 호출에 `AbortController` 5초 timeout 적용 | **70초 → 7.6초** — 약 9배 단축, 사용자 체감 응답 정상화 |
| **4** | `openPicked` 빈 배열일 때 **닫힌 picked spot 유지 + 휴무 사유와 시간 변경 안내** 함께 표시하는 로직 추가 | NO_COURSE 사라지고, 사용자가 "왜 안 되는지 + 어떻게 해야 하는지" 즉시 이해 가능 |

**+ 프롬프트 튜닝**
- narrative 톤: 형식적 → **"미리 다녀온 사람의 일기"처럼 1인칭**
- bonding 미션: 추상적 → **"손주가 할머니께 학창시절 이야기 듣기"** 같은 구체적 행동

## 슬라이드 13 — 우리 팀 서비스를 마무리하며

### 왼쪽: 기대효과 & 발전계획

**제품 관점 (Product)**
- "휠체어 어머니와 못 가" → "**할머니도 같이 갈 수 있어**"로 가족 여행의 가능성 확장
- 무장애 + 휴무 + 응급실 확인을 **수십 개 탭 → 한 화면**으로 압축
- "다른 조합 보기"로 사용자가 능동적으로 코스 다양화

**사업 관점 (Business)**
- 시·도 4개 → **17개 전국 확대** (sigungu 매핑 데이터 확장만으로 가능한 구조)
- 외국인 무장애 관광객 시장 진입 (KTO 다국어 API 8개 활용 — 영문/일문/중문 등)
- B2B 확장 — **요양시설·복지관·여행사**의 무장애 단체여행 기획 도구로 제공 가능

**기술 관점 (Technology)**
- Ennoia preset 2단 구조 (추론전용 + KTO MCP) — **데이터 수집과 추론 분리 패턴** 검증
- 14종 외부 API의 fallback chain + 5초 timeout 패턴 — 신뢰성·속도 양립
- 행정안전부 EPSG:5174 좌표 → WGS84 변환, 법정동 코드 ↔ TourAPI sigunguCode 매핑 등 **공공데이터 통합 노하우** 확보
- 시각 약자 대응 (TTS 동선 안내), 음성 입력 등 접근성 확장 로드맵

### 오른쪽: 우리 팀 소감

**한승범 (팀장)**
> Ennoia 플랫폼을 처음 다루며 MCP·preset·사용자별 인증 체계가 처음엔 낯설었지만, 한 번 익히고 나니 KTO 63개 도구를 LLM이 자동으로 호출하는 모습이 강력했습니다. **"플랫폼이 통합·인증을 책임지고, 우리는 도메인 로직에 집중"** 한다는 가치를 직접 체감했습니다.

**생성형 AI 사용 후기**
> 우리 코드의 LLM 추론 부분(체력 시뮬·세대 분기·narrative 생성)은 **LLM 없이 결정론적 fallback으로도 동작하도록 설계**했지만, LLM이 합쳐졌을 때 사용자가 받는 "1인칭 일기"의 따뜻함은 결정론 코드로는 만들 수 없는 가치였습니다. 특히 multiGen narrative에서 "근정전에서 손주가 할머니께 학창시절 이야기 듣기" 같은 **세대 연결 bonding 미션**을 LLM이 스스로 만들어내는 모습이 인상적이었습니다. 생성형 AI는 단순히 답을 생성하는 것이 아니라 **사람과 사람 사이의 연결**을 디자인할 수 있는 도구라는 것을 배웠습니다.
